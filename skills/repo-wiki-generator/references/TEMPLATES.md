# Page Templates

Three page types. Each subagent generating a page picks the matching template and fills it in. Every page ends with the same `Sources:` footer convention.

Placeholders use `{{double-braces}}`. The literal sections are required; sub-bullets describe what goes inside.

---

## Common header (all page types)

Every page starts with this block:

```markdown
# {{Page Title}}

> Indexed at commit `{{short-sha}}` on {{ISO-8601 date}} · [view on GitHub]({{repo_url}}/tree/{{sha}})

## Relevant source files

- [{{path/file1.ext}}]({{repo_url}}/blob/{{sha}}/{{path/file1.ext}})
- [{{path/file2.ext}}]({{repo_url}}/blob/{{sha}}/{{path/file2.ext}})
- ...
```

The "Relevant source files" block lists every file the page draws claims from. Citations later in the page must reference files from this list.

## Citation format (canonical)

### Inline (within prose)

```markdown
The reducer is implemented in [src/store/reducer.ts#L42]({{repo_url}}/blob/{{sha}}/src/store/reducer.ts#L42)
and dispatched from [src/store/index.ts#L18]({{repo_url}}/blob/{{sha}}/src/store/index.ts#L18).
```

### Section footer

```markdown
Sources: [src/store/reducer.ts:L1-L80]({{url}}) [src/store/index.ts:L1-L40]({{url}})
```

- Space-separated, no commas
- Listed in rough order of relevance (most important first)
- One footer per H2 section; the "Relevant source files" block at the top is the page-level summary

### Anchor convention

- Single line: `file.ext#L42` → `file.ext#L42`
- Range: `file.ext:L1-L80` (the colon is for the label; the URL uses `#L1-L80`)

Example URL:

```text
https://github.com/owner/repo/blob/abc1234/src/foo.ts#L1-L80
```

## Table conventions

Three standard tables only — keep formats consistent across pages.

### Inventory (2-column)

| Item | Description |
| ---- | ----------- |

Used for: module lists, command lists, file-category lists.

### Categorization (3-column)

| Type | Description | Example |
| ---- | ----------- | ------- |

Used for: module/variant taxonomies, configuration modes.

### Reference (3–4 column)

| Name | Type | Default | Purpose |
| ---- | ---- | ------- | ------- |

Used for: function signatures, config options, env vars. Inline code (`backticks`) for the Name column.

## Voice and length

- Third person, declarative ("X uses Y", not "We use Y" or "You should use Y").
- Present indicative tense.
- 2–4 sentences per paragraph; longer paragraphs almost always benefit from being split.
- Code identifiers always in `backticks`.
- File paths always linked, never plain text.
- Acronyms expanded on first use: "Server-Side Rendering (SSR)".
- **No callouts** (no Note/Warning/Tip blocks). Flat prose only.
- No hedging ("This may be useful…", "It is generally…"). State directly; the citation is the proof.
- Target ~1 citation per 30 words on category pages.

### Length targets

| Page type              | Words                             |
| ---------------------- | --------------------------------- |
| Overview (`README.md`) | 800–1,500                         |
| Category page          | 1,500–2,500                       |
| Detail page            | 600–1,200                         |
| Glossary               | 50–80 entries, one paragraph each |
