# Output Templates

Templates for the five artifacts written to the output directory (default
`docs/review-intelligence/`). Placeholders use `{{DOUBLE_BRACES}}`; substitute
**every** one, including `{{OUTPUT_DIR}}`. Delete any section that has no content
rather than emitting an empty heading.

Every artifact starts with the provenance block so a reader can tell how much weight
the document carries and when it went stale.

## Common provenance header

Goes at the top of every generated file, immediately after the H1.

```markdown
> Generated by `pr-review-intelligence` on {{DATE}} from {{N_PRS}} merged
> {{PR_OR_MR}}s in [{{REPO_SLUG}}]({{REPO_URL}}) ({{N_THREADS}} review threads,
> {{N_SCANNED}} scanned, {{YIELD}}% carried review discussion).
> Regenerate with `pr-review-intelligence` when review practice shifts.
```

When yield is below 10%, append this sentence — a thin corpus must announce itself:

```markdown
> **Thin corpus.** Only {{YIELD}}% of merged {{PR_OR_MR}}s carried review
> discussion, so these findings rest on a narrow sample. Treat them as hypotheses
> until confirmed by a larger run.
```

## Template A — review-guidelines.md

The primary artifact: ranked, actionable rules for whoever reviews the next change.

```markdown
# Review Guidelines

{{PROVENANCE_HEADER}}

What reviewers on this repository actually ask for, mined from merged
{{PR_OR_MR}} discussions and ranked by how often each point is raised and how
often it is acted on.

Read [do-not-flag.md](./do-not-flag.md) alongside this file. Knowing what this
team does *not* want raised matters as much as knowing what it does.

## How to use this

Rules are grouped by the paths they apply to. Load the groups matching the files
under review; skip the rest. Each rule carries the evidence it rests on — follow
the citations when a rule seems wrong for the change in front of you.

`Adherence` is the share of times this team acted on the feedback. A rule below
0.6 is a live disagreement, not settled practice; raise it as a question rather
than a defect.

## Priority rules

Highest-scoring rules across the corpus, regardless of area.

### {{RULE_TITLE}}

- **Rule** — {{IMPERATIVE_ONE_SENTENCE}}
- **Where** — `{{GLOB}}`{{, `GLOB2`}}
- **Detect** — {{WHAT_TO_LOOK_FOR_IN_A_DIFF}}
- **Why** — {{TEAM_REASONING}} > "{{VERBATIM_REVIEWER_QUOTE}}" — {{PR_LINK}}
- **Exception** — {{BOUNDARY_FROM_A_REVERSAL_THREAD}}
- **Evidence** — {{N}} {{PR_OR_MR}}s · adherence {{ADHERENCE}} · {{CATEGORY}} ·
  {{PR_LINK_1}}, {{PR_LINK_2}}{{, PR_LINK_3}}

## By area

### `{{AREA_GLOB}}`

{{ONE_LINE_ON_WHAT_THIS_AREA_IS}}

{{REPEAT_RULE_BLOCKS}}

## Single-occurrence observations

Patterns seen exactly once. Below the evidence threshold for a rule, kept as
hypotheses for the next run.

| Observation | Category | {{PR_OR_MR}} |
| --- | --- | --- |
| {{PATTERN}} | {{CATEGORY}} | {{PR_LINK}} |
```

Omit the **Exception** line unless a reversal thread actually produced a boundary.
Never write "None" — an absent line reads correctly; a "None" line reads as a claim
that no exceptions exist.

## Template B — patterns/&lt;area&gt;.md

One file per area that has at least one Wrong/Correct pair recoverable from the
corpus. These carry the project-specific idiom that no generic reviewer could infer.

Do not generate a pattern file for an area with no concrete code pair — a rule in
`review-guidelines.md` is sufficient on its own.

````markdown
# {{AREA_NAME}} Patterns

{{PROVENANCE_HEADER}}

Applies to `{{GLOB}}`.

## {{PATTERN_NAME}}

{{ONE_PARAGRAPH_ON_THE_CONVENTION_AND_WHY_IT_EXISTS}}

### Anti-pattern

```{{LANG}}
{{CODE_AS_ORIGINALLY_WRITTEN}}
```

{{WHAT_THE_REVIEWER_OBJECTED_TO}}

### Correct

```{{LANG}}
{{CODE_AFTER_THE_FIX}}
```

> "{{VERBATIM_REVIEWER_QUOTE}}" — {{PR_LINK}}

**Reference implementations** — {{REPO_FILE_LINK_1}}, {{REPO_FILE_LINK_2}}

**Evidence** — {{N}} {{PR_OR_MR}}s · adherence {{ADHERENCE}} · {{PR_LINKS}}
````

Both code blocks must come from real diffs in the corpus. If the corrected form is
not recoverable from the thread, cite a reference implementation in the repo instead
and omit the `### Correct` block. Never author a plausible-looking "correct" example
— an invented example in a pattern file propagates as fact.

## Template C — do-not-flag.md

The suppression list. This is what keeps a mined ruleset from becoming more noise.

```markdown
# Do Not Flag

{{PROVENANCE_HEADER}}

Feedback this team has repeatedly declined. Raising these wastes review cycles and
trains the team to ignore review output.

Each entry records the team's stated reason. The reason is what distinguishes a
legitimate exception from a genuine instance — read it before deciding a case is
different.

## Declined by reviewers

Points raised by humans and consciously not acted on.

### {{PATTERN}}

- **Do not flag** — {{WHAT_NOT_TO_RAISE}}
- **Stated reason** — > "{{VERBATIM_AUTHOR_QUOTE}}" — {{PR_LINK}}
- **Still flag when** — {{THE_CASE_THAT_REMAINS_LEGITIMATE}}
- **Evidence** — declined {{N}} times · {{PR_LINKS}}

## Declined bot suggestions

Automated review comments this team consistently ignored. Direct evidence of what
it considers noise.

| Suggestion | Raised | Addressed | {{PR_OR_MR}}s |
| --- | --- | --- | --- |
| {{PATTERN}} | {{N}} | {{N}} | {{PR_LINKS}} |

## Weak evidence

Declined once or twice — below the suppression threshold. Not yet a rule; listed so
the next run can confirm or drop them.

| Pattern | Times declined | {{PR_OR_MR}} |
| --- | --- | --- |
| {{PATTERN}} | {{N}} | {{PR_LINK}} |
```

The **Still flag when** line is mandatory on every entry. A suppression rule without
a boundary will eventually silence a real defect, and that is a worse failure than
the noise it was written to prevent.

## Template D — feedback-loop-report.md

Human-facing. About the review *process*, not about code. This is the artifact an
engineering lead reads.

```markdown
# Review Feedback Loop Report

{{PROVENANCE_HEADER}}

How review actually runs on this repository: what gets raised, what gets fixed,
and where the loop costs more than it returns.

## At a glance

| Metric | Value |
| --- | --- |
| {{PR_OR_MR}}s analyzed | {{N}} of {{N_SCANNED}} scanned ({{YIELD}}% had discussion) |
| Review threads | {{N}} |
| Addressed | {{N}} ({{PCT}}%) |
| Declined | {{N}} ({{PCT}}%) |
| Open at merge | {{N}} ({{PCT}}%) |
| Median change-request rounds | {{N}} |
| Bot-initiated threads | {{N}} ({{PCT}}%) |

{{IF_GITLAB}}Change-request rounds on GitLab are approximated from commits pushed
after the first review note; GitLab has no explicit change-request state.

## Where feedback concentrates

| Category | Threads | Addressed | Adherence |
| --- | --- | --- | --- |
| {{CATEGORY}} | {{N}} | {{N}} | {{ADHERENCE}} |

{{TWO_TO_FOUR_SENTENCES_ON_WHAT_THE_DISTRIBUTION_SHOWS}}

## Cost concentrations

Patterns driving the most review rounds. Each is a candidate for elimination
rather than better reviewing.

### {{PATTERN}}

Raised in {{N}} {{PR_OR_MR}}s, costing roughly {{N}} extra review rounds.

{{WHY_IT_KEEPS_HAPPENING}}

**Cheaper fix** — {{LINT_RULE_CI_CHECK_TEMPLATE_OR_DOC}}

## Move these out of review

Findings a tool could catch without a human or a language model. Every one moved
to tooling is a round trip that stops happening.

| Pattern | Times raised | Suggested enforcement |
| --- | --- | --- |
| {{PATTERN}} | {{N}} | {{LINT_RULE_OR_CI_CHECK}} |

## Unresolved disagreements

Patterns with adherence below 0.6 — raised often, acted on inconsistently. These
need a team decision, not a review rule.

| Pattern | Raised | Addressed | Adherence |
| --- | --- | --- | --- |
| {{PATTERN}} | {{N}} | {{N}} | {{ADHERENCE}} |

## Coverage caveats

{{WHAT_THIS_ANALYSIS_COULD_NOT_SEE}}
```

The **Coverage caveats** section is mandatory. State plainly what the corpus missed:
review that happened in chat or in person, squashed PRs with no thread history,
truncated fetches, a sampling window that excluded a major refactor. A report that
does not bound its own claims invites over-reading.

## Template E — routing stub

Written to `{{OUTPUT_DIR}}/AGENTS-snippet.md`, for the user to paste into their
`AGENTS.md`, `CLAUDE.md`, or `.github/copilot-instructions.md`. Never edit those
files directly — they are the user's, and may carry instructions this skill has no
business rewriting.

```markdown
## Code review guidelines

Mined from this repository's own {{PR_OR_MR}} review history. Load the guideline
file matching the files under review.

- Always read: [{{OUTPUT_DIR}}/review-guidelines.md]({{OUTPUT_DIR}}/review-guidelines.md)
- Always read: [{{OUTPUT_DIR}}/do-not-flag.md]({{OUTPUT_DIR}}/do-not-flag.md)

Area-specific patterns:

| When reviewing | Read |
| --- | --- |
| `{{GLOB}}` | [{{OUTPUT_DIR}}/patterns/{{SLUG}}.md]({{OUTPUT_DIR}}/patterns/{{SLUG}}.md) |
```

Keep the stub short. Its whole purpose is routing — duplicating rule content here
guarantees the copy drifts from the source.
