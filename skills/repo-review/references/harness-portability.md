# Running this skill outside Claude Code

The skill is prose; the six reviewers are agent definitions. Prose ports for
free — agent definitions do not. This file records what was verified, how, and
what is still unproven.

## Verification status

| Harness | Skills | Custom agents | Enforcement of read-only | Status |
|---|---|---|---|---|
| Claude Code | native | `agents/*.md` | tool allowlist omits `Edit`/`Write` | **verified** (native) |
| Pi | `--skill` | `~/.pi/agent/agents/*.md` (needs `pi-subagents`) | tool allowlist | **verified by running** |
| Codex | `~/.codex/skills` | `~/.codex/agents/*.toml` | `sandbox_mode = "read-only"` | flags read from CLI; **run unverified** |
| Gemini CLI | `gemini skills` | `~/.gemini/agents/*.md` | tool allowlist | documented only; **run unverified** |

Pi was exercised end to end: the generated `security-reviewer` reviewed a
planted file and returned a contract-conformant report — `SEC-*` IDs, the
P0–P3 scale, `file:line` evidence, the output-budget line, and a **redacted**
secret (`sk_live_…`). The contract survived a different harness and a different
model. Codex and Gemini rows come from their CLIs and docs, not from a run.

## Skills are already portable

`~/.agents/skills/` is a working cross-runtime convention — Gemini discovers
skills there, and Codex keeps `~/.codex/skills`. Both read the same
`SKILL.md` + YAML frontmatter this repo already uses. No changes were needed.

## Agents are not

There is **no** `~/.agents/agents/`. Each harness looks only in its own
directory, and none of them look inside this plugin. Hence
`scripts/install-agents.sh`, which symlinks the generated wrappers into place.

`agents/*.md` (Claude Code format) is the single source of truth.
`generated/agents/**` is generated by `scripts/sync-agents.sh` — never edit it.

## Tool vocabularies do not converge

| Action | Claude Code | Pi | Gemini |
|---|---|---|---|
| read a file | `Read` | `read` | `read_file`, `read_many_files` |
| search contents | `Grep` | `grep` | `grep_search` |
| find/list files | `Glob` | `find`, `ls` | `glob`, `list_directory` |
| run a command | `Bash` | `bash` | `run_shell_command` |
| edit / write | `Edit` / `Write` | `edit` / `write` | `replace` / `write_file` |

Codex has no allowlist at all. It uses a real sandbox, so **the read-only
guarantee is stronger there than on Claude Code** — `sandbox_mode` is enforced
by the runtime rather than by which tools were offered.

## The failure mode that makes this dangerous

Foreign tool names **fail closed** — verified on pi, which grants nothing rather
than everything. Safe. But it fails *silently*:

```
pi -p -t Read,Grep,Glob "create PROOF.txt"    -> exit 0, no output, no file
pi -p -t read,write,bash "create PROOF.txt"   -> file created  (control)
pi -p -t read,grep,find,ls "create PROOF.txt" -> refused, explained why
```

A reviewer shipped with the wrong vocabulary returns **nothing**, and an
orchestrator cannot tell "reviewed, found nothing" from "had no tools". Six
empty sections synthesise into a confident clean bill of health on a broken
repo — the worst output this skill can produce.

Two defences, both required:

1. `scripts/sync-agents.sh` treats an unmappable tool name as a **hard error**,
   so a bad mapping breaks the build instead of shipping.
2. The orchestrator treats an empty review that cites no files read as a
   **misconfiguration, not a clean dimension** (see SKILL.md Phase 1).

## When there is no subagent capability

Pi needs `pi install npm:pi-subagents`. Codex ships `multi_agent` as a stable
feature, on by default (verified: `codex features list`). If no subagent
mechanism exists, the orchestrator runs the six dimensions sequentially in its
own context and labels the report single-context — see SKILL.md Phase 1.

## Setup

```bash
scripts/sync-agents.sh                      # regenerate (CI runs --check)
scripts/install-agents.sh --list
scripts/install-agents.sh --harness pi      # or gemini | codex | all
scripts/install-agents.sh --harness pi --uninstall
```

Installs are user-scope symlinks, so a plugin update propagates with no
re-install. A real file already at a target path is never overwritten.
